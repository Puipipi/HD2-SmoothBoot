# 自动保护与分别调度：已停止的研究记录

2026-10-02（Asia/Shanghai）。用户取消新的自动分类/分别调度方案，继续使用原调度器和排除名单。随后要求：若无法可靠识别功能被托管破坏的模组，就移除弹窗。当前3.0.21已移除弹窗，只新增 LTE `lte/helmet_cape_passives` 默认排除项；没有新增 RatInPlat Armor Transmog 排除项。本文是已停止的研究记录，不是实现计划或新调度器完成声明。

## 真实发现

- 旧3.0.20提示曾显示 Maelstrom Traverse 和 mods/codex/gun_calibration，用户确认过位置及隐藏时机。3.0.21按最新要求移除整个提示。
- 评论只报告 LTE 头盔/披风模组不能创建自定义变体；已有被动仍在，RatInPlat 护甲幻化正常。不能误写成两个模组都冲突。
- Helmet and Cape Passives 的作者原始包发布 `_G.LTE_helmet_cape_passives`；状态表包括 revision、phase、writes、failures、done。
- 它的 `tick()` 在判断 `state.done` 之前运行值监视和已应用数据的重新检查。因此 done=true **不等于不再运行或不再写入**，不能靠“初始化完成”就认定可以跳帧。
- 作者回调先调用 original_update，再运行 safe_tick，并原样返回下游结果。这个结构允许研究独立调度其自身工作，但需要确认其 tick 计数重试/重新应用的时机没有被破坏。
- RatInPlat 的 Armor Transmog 0.1.5 发布页说明它处理军械库和任务前装备界面，更新记录包含控制器轮询、装备恢复和双词条问题。当前已部署列表没有此评论中完整组合，不能称已复现或解决该组合。
- 看门狗的实际调用链包含 Smooth 的多个 writer gate。必须按回调自身时间核算，不能用整链时间给某模组贴“耗时”的标签。

## 可行结构

1. 游戏本体每帧运行，界面/输入回调每帧运行。
2. 单独的回调分发器包装可证明只有一个下游入口的标准模组回调。跳过该模组时仍调用其下游，不跳过整个游戏 update。
3. 初始观察期核对：下游每帧恰好一次、参数不变、返回值完整（含 nil）、不重入、不漏掉新注册回调。回调不符合约定则不接管。
4. 自动测量自身工作：总时间减去下游耗时。达到持续阈值后，只有已确认可延后的后台扫描进入降频；初始化和场景重新初始化恢复全速。
5. 自动保护按实际行为/状态识别：输入、UI、原生写入/重新应用、初始化中、未知。固定模组名仅作为旧版本的兼容兜底，不是通用分类规则。
6. 未知回调保留全速且只保护该回调。不能因为一个回调无法确认，就关闭其他已验证回调的节流。
7. 警告只根据实际调度器状态出现。仅发现模组、耗时偏高、名单匹配都不能称冲突已发生。

## 自动识别的限制

Lua 回调的耗时不能证明用途；直接 FFI 指针写入不必经过统一的可观测 API。源码关键词、done/status 名称和几秒没有出错，也不能证明可以安全降低调用频率。需要作者能力声明、已核对的回调契约/适配，或实机功能验证，才能从“未知”转为“可延后”。不承诺任意第三方模组无需验证即可全自动且保证所有功能。

## 未执行的研究验收设想

以下设想未执行，用户已取消，不得擅自继续：验证标准链与 Watchdog 同时存在时，游戏本体、输入/UI 回调每帧一次，后台回调单独降频，多个回调并存、重挂钩、异常和切场景保留正确调用。评论中的完整组合未安装，不得把已有舰船画面当作该组合验证。

3.0.21只修补现有排除规则：内部排除对象存在时整段托管链保留全速，并关闭针对该段的启动暂停/熔断。其余链保留原策略；不是独立调度实现。
