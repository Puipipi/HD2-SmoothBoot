# SmoothBoot 内存检查与 C4 专用代码移除（2026-10-09）

反馈只有“有人说存在内存泄漏”，没有版本、内存曲线或复现步骤。审查了公开标签
v3.0.45 与工作区 3.0.48；本机最近日志也显示 3.0.48。随后按用户要求，候选
3.0.49 完整移除 C4 专用运行逻辑，保留通用调度和工作区原有修改。

发现一处已修复的通用引用残留；尚不能确认它导致反馈者的持续内存上涨或崩溃。
没有操作游戏、附加游戏进程、部署或发布本候选版。

## 通用引用修复

开局暂停结束后 `APorig` 原本仍保存 `tbl=foreign_state`。外部模组后来替换或
删除状态时，旧状态及可达对象仍被 Smooth 的长期闭包引用。恢复完成后清空
`APorig` 和 `AP.seen_keys` 即可释放。这是一次开局保留，不能直接解释每帧持续泄漏。

弱引用观察器配合两次完整 GC，在 lupa LuaJIT 2.1 和游戏现有 `lua51.dll` 的
独立 Lua state 中均复现：修复前旧状态残留 1 个，修复后 0 个。游戏 DLL 的测试
不附加游戏进程，也不能代替实机验证。合成状态含 1 MiB payload。

## C4 专用代码移除

删除读取池、输入/上下文/原生分块、各作用域适配、自动发现、专用快照与
CPU/读取诊断，以及配置解析和生成。删除只针对这些适配器的测试/夹具；共享
Lua 测试 VM 已独立为 `lua_test_vm.py`，其他通用测试继续使用它。

新回归覆盖旧 `c4_*` 配置全部打开时依然不导出适配器、不替换第三方读取方法，
普通回调逐帧执行且保留返回值，旧配置文件字节不变；首次生成的配置没有这些选项。

删除前还发现 C4Pool.records 强引用废弃 API。在明确执行 128 次接受的 attach
压力场景中可保留全部 128 个；这不是正常任务复现。C4 1.11 原码在初始化时创建
一次读取器，不能外推为每局或每分钟泄漏。该专用模块现在已整体删除，不再使用
先前试验的弱键修补。历史源码及测量仅作为本地审查证据保留，不进入候选包。

## 当前验证

- 全部剩余 unittest：57 项通过。删除了适配器专用测试，因此数量低于移除前的 125 项。
- LuaJIT 编译及共享 FFI 声明检查通过，运行源码声明仅含 GetModuleHandleA/GetProcAddress。
- 512 次替换 render 闭包后，旧闭包均可回收。
- 固定回调完整运行 120,000 帧，模拟约 1,000 秒；每 20,000 帧完整 GC。
  同时覆盖 `gc_pause=0` 与 `gc_pause=400`。
- 当前测量：游戏 DLL 独立 VM 的保留堆范围约 7.48 KiB，lupa 约 4.94 KiB；
  测试场景未出现随帧数线性增长。开局旧状态残留均为 0。
- 构建出的候选包需重启游戏后安装；当前进程已装入的旧适配无法靠替换磁盘文件撤销。
- 额外单独运行开局暂停旧脚本通过。历史 2.17 writer-hold 脚本仍调用已不存在的
  `wh_release` 接口，运行失败；本次修改前的 3.0.48 同样失败，已保存基线对照。
  它不在上述 57 项 unittest 中，不能将“57 项通过”表述为仓库所有历史脚本均通过。
  现行 writer accounting、启动放行、Watchdog 探针和重入测试均已通过。

## 尚未证实的部分

缓存 `chunk_cache`、HUD 字段与 writer gate 标记使用弱键。日志追加属于磁盘增长，
不是将全部历史保存到 Lua 内存。`gc_pause` 默认 400，本机配置 0，Smooth 不覆盖
本机该参数。未增加强制 GC 或全局采样；FirstFault 接入继续停用。

隔离 Lua 堆检查不覆盖其他模组、原生堆、进程分配器及显存，也不证明所有模组组合
安全。仍缺同列表多局实机内存曲线及反馈版本；不能把本次结果表述为“已修复反馈者
的内存泄漏”。候选版需要用户实机确认 C4 原功能、正常进出任务与长期内存表现。
